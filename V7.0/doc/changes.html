The Coq Proof Assistant

Changes from Coq V6.3.1 to Coq V7



Overview

The new major version number is justified by a deep restructuration of the implementation code of Coq. For the end-user, Coq V7 provides the following novelties:

  • A more high-level tactic language called Ltac (see section 2)
  • A primitive let-in construction (see section 1.1) which can also be used in Record definitions (as suggested by Randy Pollack)
  • Structuration of the developments in libraries and use of the dot notation to access names (see section 1.2)
  • A search facilities by pattern provided by Yves Bertot (see section 3.1)
  • A ``natural'' syntax for real numbers (see section 1.3)
  • New tactics (and developments) for real numbers (see section 2.2)
  • The tactic Field which solves equalities using commutative field theory (see section 2.2)
  • The tactic Fourier to solve inequalities, developed by Loïc Pottier has been integrated
  • A command to export theories to XML to be used with Helm's publishing and rendering tools (see section 3.2)
  • A new implementation of extraction (see section 5)
Incompatibilities are described in section 7. Please notice that Program/Realizer is no more available in Coq V7.

Developers of tactics in ML are invited to read section 6.

Changes between Coq V7beta and Coq V7
Some functionalities of Coq V6.3 that were not available in Coq V7beta has been restored :
  • A new mechanism for extraction of ML programs has been introduced.
  • Correctness is now supported.
  • Syntax for user-defined tactics calls does not require extra parenthesis.
  • Elim can be called even for non-inductive objects when the apropriate elimination lemma exists.
  • User defined tokens with arbitrary combination of letters and symbols have been reintroduced.

1   Language

1.1   Primitive let ... in ... construction

The let ... in ... syntax in V6.3.1 was implemented as a macro. It is now a first-class construction.

Coq < Require ZArith.

Coq < Definition eight := [two:=`1 + 1`][four:=`two + two`]`four + four`. 
eight is defined

Coq < Print eight.
eight = [two:=`1+1`][four:=`two+two`]`four+four`
     : Z

Local definitions and Remark inside a section now behaves as local definitions outside the section.

Coq < Section A.

Coq < Local two := `1 + 1`.
two is defined

Coq < Definition four := `two + two`.
four is defined

Coq < End A.
four is discharged.

Coq < Print four.
four = [two:=`1+1`]`two+two`
     : Z

The unfolding of a reference with respect to a definition local to a section is performed by d rule. But a ``let ... in ...'' inside a term is not concerned by d reduction. Commands to finely reduce this kind of expression remain to be provided.
Alternative syntax
A less symbolic but equivalent syntax is available as :
let two = `1 + 1` in `two + two`.

Local definitions in records
Local definitions can be used inside record definitions as suggested by Randy Pollack :
Coq < Record local_record : Set := {x:nat; y:=O; H:x=y}.
local_record is defined
local_record_ind is defined
local_record_rec is defined
local_record_rect is defined

Coq < Print local_record.
Inductive local_record  : Set :=
      Build_local_record : (x:nat)[y:=(0)]x=y->local_record

Coq < Print x.
x = 
[l:local_record]
 Cases l of (Build_local_record x x0) => ([y:=(0)][_:(x=y)]x x0) end
     : local_record->nat

Coq < Print y.
y = [_:local_record](0)
     : local_record->nat

Coq < Check H.
H
     : (l:local_record)(x l)=(y l)

1.2   Libraries and qualified names

Identifiers
An identifier is any string beginning by a letter and followed by letters, digits or simple quotes. The bug with identifiers ended by a number greater than 230 is fixed!

Libraries
The theories developed in Coq are now stored in libraries. A library is characterized by a name called root of the library. By default, two libraries are defined at the beginning of a Coq session. The first library has root name Coq and contains the standard library of Coq. The second has root name Scratch and contains all definitions and theorems not explicitly put in a specific library.

Libraries have a tree structure. Typically, the Coq library contains the (sub-)libraries Init, Logic, Arith, Lists, ... The ``dot notation'' is used to write (sub-)libraries. Typically, the Arith library of Coq standard library is written ``Coq.Arith''.
Remark: no space is allowed between the dot and the following identifier, otherwise the dot is interpreted as the final dot of the command!
Libraries and sublibraries can be mapped to physical directories of the operating system using the command

Add LoadPath physical_dir as (sub-)library.
Incidentally, if a (sub-)library does not already exists, it is created by the command. This allows users to define new root libraries.

A library can inherit the tree structure of a physical directory by using the command

Add Rec LoadPath physical_dir as (sub-)library.
At some point, (sub-)libraries contain modules which coincides with files at the physical level. Modules themselves may contain sections, subsections, ... and eventually definitions and theorems.

As for sublibraries, the dot notation is used to denote a specific module, section, definition or theorem of a library. Typically, Coq.Init.Logic.Equality.eq denotes the Leibniz' equality defined in section Equality of the module Logic in the sublibrary Init of the standard library of Coq. By this way, a module, section, definition or theorem name is now unique in Coq.

Absolute and short names
The full name of a library, module, section, definition or theorem is called absolute. The final identifier eq is called the base name. We call short name a name reduced to a single identifier. Coq maintains a name table mapping short names to absolute names. This greatly simplifies the notations and preserves compatibility with the previous versions of Coq.

Visibility and qualified names
An absolute path is called visible when its base name suffices to denote it. This means the base name is mapped to the absolute name in Coq name table.

All the base names of sublibraries, modules, sections, definitions and theorems are automatically put in the Coq name table. But sometimes, names used in a module can hide names defined in another module. Instead of just distinguishing the clashing names by using the absolute names, it is enough to prefix the base name just by the name of its containing section (or module or library). Such a name built from single identifiers separated by dots is called a qualified name. Especially, both absolute names and short names are qualified names. Root names cannot be hidden in such a way fully qualified (i.e. absolute names) cannot be hidden.

Examples:

Coq < Check O.
O
     : nat

Coq < Definition nat := bool.
nat is defined

Coq < Check O.
O
     : Datatypes.nat

Coq < Check Datatypes.nat.
Datatypes.nat
     : Set

Requiring a file
When a ``.vo'' file is required in a physical directory mapped to some (sub-)library, it is adequately mapped in the whole library structure known by Coq. However, no consistency check is currently done to ensure the required module has actually been compiled with the same absolute name (e.g. a module can be compiled with absolute name Mycontrib.Arith.Plus but required with absolute name HisContrib.ZArith.Plus).

The command Add Rec LoadPath is also available from coqtop and coqc by using option -R (see section 4).

1.3   Syntax extensions

``Natural'' syntax for real numbers
A ``natural'' syntax for real numbers and operations on reals is now available by putting expressions inside pairs of backquotes.

Coq < Require Reals.

Coq < Check ``2*3/(4+2)``.
``2*3/(4+2)``
     : R
Remark: A constant, say ``4``, is equivalent to ``(1+(1+(1+1)))``.

Infix
was inactive on pretty-printer. Now it works.

Consecutive symbols
are now considered as an unique token. Exceptions have been coded in the lexer to separate tokens we do not want to separate (for example A->~B), but this is not exhaustive and some spaces may have to be inserted in some cases which have not been treated (e.g. ~<nat>O=O should now be written ~ <nat>O=O).

The command syntactic class for Grammar
has been renamed constr consistently with the usage for Syntax extensions. Entries command1, command2, ... are renamed accordingly. The type List in Grammar rules has been renamed ast list.

Default parser in Grammar and Syntax
The default parser for right-hand-side of Grammar rules and for left-hand-side of Syntax rule was the ast parser. Now it is the one of same name as the syntactic class extended (i.e. constr, tactic or vernac). As a consequence, << ... >> should be removed.

On the opposite, in rules expecting the ast parser, << ... >> should be added in the left-hand-side of Syntax rule. As for Grammar rule, a typing constraint, ast or ast list needs to be explicitly given to force the use of the ast parser. For Grammar rule building a new syntactic class, different from constr, tactic, vernac or ast, any of the previous keyword can be used as type (and therefore as parser).

See examples in appendix.

Syntax overloading
Binding of constructions in Grammar rules is now done with absolute paths. This means overloading of syntax for different constructions having the same base name is no longer possible.

Timing or abbreviating a sequence of commands
The syntax [ phrase1 ... phrasen ]. is now available to group several commands into a single one (useful for Time or for grammar extensions abbreviating sequence of commands).

1.4   Miscellaneous

Pattern aliases
of dependent type in Cases expressions are currently not supported.

1.5   Libraries

The names of directories in theories has been changed. The directory theories/Zarith has been renamed theories/ZArith between Coq V7.0beta and V7.0.

A new directory theories/IntMap has been added which contains an efficient representation of finite sets as maps indexed by binary integers. This development has been developed by J. Goubault and was previously an external contribution.

Some definitions, lemmas and theorems have been added or reorganised, see the Library documentation for more information.

2   Tactics

2.1   A tactic language: Ltac

Ltac is a new layer of metalanguage to write tactics and especially to deal with small automations for which the use of the full programmable metalanguage (Objective Caml) would be excessive. Ltac is mainly a small functional core with recursors and elaborated matching operators for terms but also for proof contexts. This language can be directly used in proof scripts or in toplevel definitions (Tactic Definition). It has been noticed that non-trivial tactics can be written with Ltac and to provide a Turing-complete programming framework, a quotation has been built to use Ltac in Objective Caml. Ltac has been contributed by David Delahaye and, for more details, see the Reference Manual. Regarding the foundations of this language, the author page can be visited at the following URL:
http://logical.inria.fr/~delahaye/

Tactic debuger
Debug ( On | Off )
turns on/off the tactic debuger for Ltac. This is still very experimental and no documentation is provided yet.

2.2   New tactics

Field
written by David Delahaye and Micaela Mayero solves equalities using commutative field theory. This tactic is reflexive and has been implemented using essentially the new tactic language Ltac. Only the table of field theories (as for the tactic Ring) is dealt by means of an part. This tactic is currently used in the real number theory. For more details, see the Reference Manual.

Fourier
written by Loïc Pottier solves linear inequations.

Other tactics and developments
has been included in the real numbers library: DiscrR proves that a real integer constant c1 is non equal to another real integer constant c2; SplitAbsolu allows us to unfold Rabsolu contants and split corresponding conjonctions; SplitRmult allows us to split a condition that a product is non equal to zero into subgoals corresponding to the condition on each subterm of the product. All these tactics have been written with the tactic language Ltac.
A development on Cauchy series, power series,... has been also added.
For more details, see the Reference Manual.

2.3   Changes in pre-existing tactics

Tauto and Intuition
have been rewritten using the new tactic language Ltac. The code is now quite shorter and a significant increase in performances has been noticed. Tauto has exactly the same behavior. Intuition is slightly less powerful (w.r.t. to dependent types which are now considered as atomic formulas) but it has clearer semantics. This may lead to some incompatibilities.

Simpl
now simplifies mutually defined fixpoints as expected (i.e. it does not introduce Fix id {...} expressions).

AutoRewrite
now applies only on main goal and the remaining subgoals are handled byHint Rewrite. The syntax is now:
Hint Rewrite ( -> | <- )* [ term1 ... termn ] in ident using tac
Adds the terms term1 ... termn (their types must be equalities) in the rewriting database ident with the corresponding orientation (given by the arrows; default is left to right) and the tactic tac which is applied to the subgoals generated by a rewriting, the main subgoal excluded.
AutoRewrite [ ident1 ... identn ] using tac
Performs all the rewritings given by the databases ident1 ... identn applying tac to the main subgoal after each rewriting step.
See the contribution contrib/Rocq/DEMOS/Demo_AutoRewrite.v for examples.

Intro hyp and Intros hyp1 ... hypn
now fail if the hypothesis/variable name provided already exists.

Prolog
is now part of the core system. Don't use Require Prolog.

Unfold
now fails when its argument is not an unfoldable constant.

Tactic Let
has been renamed into LetTac and it now relies on the primitive let-in constructions

Apply ... with ...
when instantiations are redundant or incompatible now behaves smoothly.

Decompose
has now less bugs. Also hypotheses are now numbered in order.

Linear
seems to be very rarely used. It has not been ported in Coq V7.

Program/Realizer
has not been ported in Coq V7.

3   Toplevel commands

3.1   Searching the environment

A new searching mechanism by pattern has been contributed by Yves Bertot.

SearchPattern term
displays the name and type of all theorems of the current context whose statement's conclusion matches the expression term where holes in the latter are denoted by ``?''.

Coq < Require Arith.

Coq < SearchPattern (plus ? ?)=?.
le_plus_minus_r: (n,m:nat)(le n m)->(plus n (minus m n))=m
mult_n_Sm: (n,m:nat)(plus (mult n m) n)=(mult n (S m))
plus_sym: (n,m:nat)(plus n m)=(plus m n)
plus_Snm_nSm: (n,m:nat)(plus (S n) m)=(plus n (S m))
plus_assoc_l: (n,m,p:nat)(plus n (plus m p))=(plus (plus n m) p)
plus_permute: (n,m,p:nat)(plus n (plus m p))=(plus m (plus n p))
plus_assoc_r: (n,m,p:nat)(plus (plus n m) p)=(plus n (plus m p))
plus_permute_2_in_4:
  (a,b,c,d:nat)
   (plus (plus a b) (plus c d))=(plus (plus a c) (plus b d))

Patterns need not be linear: you can express that the same expression must occur in two places by using indexed ``?''.

Coq < Require Arith.

Coq < SearchPattern (plus ? ?1)=(mult ?1 ?).
mult_n_Sm: (n,m:nat)(plus (mult n m) n)=(mult n (S m))

SearchRewrite term
displays the name and type of all theorems of the current context whose statement's conclusion is an equality of which one side matches the expression term. Holes in term are denoted by ``?''.

Coq < Require Arith.

Coq < SearchRewrite (plus ? (plus ? ?)).
plus_assoc_l: (n,m,p:nat)(plus n (plus m p))=(plus (plus n m) p)
plus_permute: (n,m,p:nat)(plus n (plus m p))=(plus m (plus n p))
plus_assoc_r: (n,m,p:nat)(plus (plus n m) p)=(plus n (plus m p))
plus_permute_2_in_4:
  (a,b,c,d:nat)
   (plus (plus a b) (plus c d))=(plus (plus a c) (plus b d))


Variants:
  1. SearchPattern term inside module1...modulen
    SearchRewrite term inside module1...modulen.

    This restricts the search to constructions defined in modules module1...modulen.

  2. SearchPattern term outside module.
    SearchRewrite term outside module1...modulen.

    This restricts the search to constructions not defined in modules module1...modulen.
Search ident.
has been extended to accept qualified identifiers and the inside and outside restrictions as SearchPattern and SearchRewrite.

SearchIsos term.
has not been ported yet.

3.2   XML output

A printer of Coq theories into XML syntax has been contributed by Claudio Sacerdoti Coen. Various printing commands (such as Print XML Module ident) allow to produce XML files from ``.vo'' files. In order to experiment these possibilities, you need to require the Coq Xml module first.

These XML files can be published on the Web, retrieved and rendered by tools developed in the HELM project (see http://www.cs.unibo.it/helm).

3.3   Other new commands

Implicits ident
associate to ident implicit arguments as if the implicit arguments mode was on.

Implicits ident [num ...num]
allows to explicitly give what arguments have to be considered as implicit in ident.

Coq < Parameter exists : (A:Set)(P:A->Prop)(x:A)(P x)->(EX x:A |(P x)).
exists is assumed

Coq < Implicits exists.

Coq < Print exists.
*** [ exists : 
(A:Set; P:(A->Prop); x:A)(P x)->(EX x0:A | (P x0)) ]
Positions [1;2;3] are implicit

Coq < Implicits exists [1].

Coq < Print exists.
*** [ exists : 
(A:Set; P:(A->Prop); x:A)(P x)->(EX x0:A | (P x0)) ]
Position [1] is implicit

3.4   Syntax standardisation

The commands on the left are now equivalent to (old) commands on the right.
Set Implicit Arguments Implicit Arguments On
Unset Implicit Arguments       Implicit Arguments Off
Add LoadPath AddPath
Add Rec LoadPath AddRecPath
Remove LoadPath DelPath
Set Silent Begin Silent
Unset Silent End Silent
Print Coercion Paths Print Path

Commands on the right remains available for compatibility reasons (except for Begin Silent and End Silent which interfere with section closing, and for the misunderstandable Print Path).

3.5   Other Changes

Final dot
Commands should now be ended by a final dot ``.'' followed by a blank (space, return, line feed or tabulation). This is to distinguish from the dot notation for qualified names where the dot must immediately be followed by a letter (see section 1.2).

Eval Cbv Delta ... in ...
The [- const], if any, should now immediately follow the Delta keyword.

4   Tools

Consistency check for .vo files
A check-sum test avoids to require inconsistent .vo files.

Optimal compiler
If your architecture supports it, the native version of coqtop and coqc is used by default.

Option -R
The -R option to coqtop and coqc now serves to link physical path to logical paths (see 1.2). It expects two arguments, the first being the physical path and the second its logical alias. It still recursively scans subdirectories.

Makefile automatic generation
coq_makefile is the new name for do_Makefile.

Error localisation
Several kind of typing errors are now located in the source file.

5   Extraction

Extraction code has been completely rewritten by J.-C. Filliâtre and P. Letouzey since version V6.3. This work is still not finished, but most parts of it are already usable. It was successfully tested on the Coq theories.

The new mechanism is able to extract programs from any Coq term (including terms at the Type level). A new mechanism to extract Ocaml modules from Coq files has been added.

However, the resulting ML term is not guaranteed to be typable in ML (the next version should incorporate automatically appropriate conversions).

Only extraction towards Ocaml programs is currently available. The ML import command is not available anymore, the command Extract Constant can be used to realize a Coq axiom by an ML program.

More information can be found in $COQTOP/contrib/extraction/README. The syntax of commands is described in the Reference Manual.

6   Developers

The internals of Coq has changed a lot and will continue to change significantly in the next months. We recommend tactic developers to take contact with us for adapting their code. A document describing the interfaces of the ML modules constituting Coq is available thanks to J.-C. Filliatre's ocamlweb documentation tool (see the ``doc'' directory in Coq source).

7   Incompatibilities

You could have to modify your vernacular source for the following reasons:

  • Any of the tactic changes mentioned in section 2.3.

  • The ``.vo'' files are not compatible and all ``.v'' files should be recompiled.

  • Consecutive symbols may have to be separated in some cases (see section 1.3).

  • Default parsers in Grammar and Syntax are different (see section 1.3).
  • Definition of D_in (Rderiv.v) is now with Rdiv and not with Rmult and Rinv as before.

  • Pattern aliases of dependent type in Cases expressions are currently not supported.

A shell script translate_V6-3-1_to_V7 is available in the archive to automatically translate V6.3.1 ``.v'' files to V7.0 syntax (incompatibilities due to changes in tactics semantics are not treated).

Appendix

We detail the differences between Coq V6.3.1 and V7.0 for the Syntax and Grammar default parsers.
Examples in V6.3.1

Grammar command command0 :=
  pair [ "(" lcommand($lc1) "," lcommand($lc2) ")" ] ->
         [<<(pair ? ? $lc1 $lc2)>>].

Syntax constr
  level 1:
  pair [<<(pair $_ $_ $t3 $t4)>>] -> [[<hov 0> "(" $t3:E ","[0 1] $t4:E ")" ]].

Grammar znatural formula :=
  form_expr [ expr($p) ] -> [$p]
| form_eq [ expr($p) "=" expr($c) ] -> [<<(eq Z $p $c)>>].

Syntax constr
  level 0:
    Zeq [<<(eq Z $n1 $n2)>>] -> 
      [[<hov 0> "`" (ZEXPR $n1) [1 0] "= "(ZEXPR $n2)"`"]].

Grammar tactic simple_tactic :=
  tauto [ "Tauto" ] -> [(Tauto)].

New form in V7.0beta

Grammar constr constr0 :=
  pair [ "(" lconstr($lc1) "," lconstr($lc2) ")" ] -> [ (pair ? ? $lc1 $lc2) ].

Syntax constr
  level 1:
    pair [ (pair $_ $_ $t3 $t4) ] -> [[<hov 0> "(" $t3:E ","[0 1] $t4:E ")" ]].

Grammar znatural formula : constr :=
  form_expr [ expr($p) ] -> [ $p ]
| form_eq [ expr($p) "=" expr($c) ] -> [ (eq Z $p $c) ].

Syntax constr
 level 0:
  Zeq [ (eq Z $n1 $n2) ] -> 
    [<hov 0> "`" (ZEXPR $n1) [1 0] "= "(ZEXPR $n2)"`"]].

Grammar tactic simple_tactic: ast :=
  tauto [ "Tauto" ] -> [(Tauto)].
