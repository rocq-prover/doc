5.2 Typing Modules

In order to introduce the typing system we must first slightly extend the syntactic class of terms and environments given in section 4.1. The environments, apart from definitions of constants and inductives will also hold any other signature elements. Terms, apart from variables, constants and complex terms, will also include access paths.

We will also need additional typing judgments:
  • E[] |- WF(T), denoting that a module type T is well-formed,

  • E[] |- M : T, denoting that a module expression M has type T in environment E.

  • E[] |- Impl : Spec, denoting that an implementation Impl verifies a specification Spec

  • E[] |- T1 <: T2, denoting that a module type T1 is a subtype of a module type T2.

  • E[] |- Spec1 <: Spec2, denoting that a specification Spec1 is more precise that a specification Spec2.
The rules for forming module types are the following:
  • WF-SIG
    WF(E;E')[]
    E[] |- WF( Sig E'  End)
  • WF-FUN
    E; ModS(X:T)[] |- WF(T')
    E[] |- WF( Funsig(X:T) T')
Rules for typing module expressions:
  • MT-STRUCT
    E[] |- WF( Sig Spec1;...;Specn  End)
    E;Spec1;...;Speci-1[] |- Impli : Speci for i=1... n
    E[] |- Struct Impl1;...;Impln  End : Sig Spec1;...;Specn  End
  • MT-FUN
    E; ModS(X:T)[] |- M : T'
    E[] |- Functor[X:T] M : Funsig(X:T) T'
  • MT-APP
    E[] |- p' : Funsig(X:T) T'           E[] |- p'' : T
    E[] |- p' p'' : T'{X/p''}
  • MT-SUB
    E[] |- M : T            E[] |- T <: T'
    E[] |- M : T'
  • MT-STR
    E[] |- p : T
    E[] |- p : T/p
The last rule, called strengthenning is used to make all module fields manifestly equal to themselves. The notation T/p has the following meaning:
  • if T= Sig Spec1;...;Specn  End then T/p= Sig Spec1/p;...;Specn/p  End where Spec/p is defined as follows:
    • Def()(c:=U:t)/p  =  Def()(c:=U:t)
    • Assum()(c:U)/p  =  Def()(c:=U:p.c)
    • ModS(X:T)/p  =  ModSEq(X:T/p.X==p.X)
    • ModSEq(X:T==p')/p  =  ModSEq(X:T==p')
    • Ind()[GP](GC:=GI )/p  =  Indp()[GP](
      GC:=GI  )
    • Indp'()[GP](
      GC:=GI  )
      /p  =  Indp'()[GP](
      GC:=GI  )
  • if T= Funsig(X:T) T' then T/p=T
  • if T is an access path or a module type name, then we have to unfold its definition and proceed according to the rules above.
The notation Indp()[GP](
GC:=GI  )
denotes an inductive definition that is definitionally equal to the inductive definition in the module denoted by the path p. All rules which have Ind()[GP](GC:=GI ) as premises are also valid for Indp()[GP](
GC:=GI  )
. We give the formation rule for Indp()[GP](
GC:=GI  )
below as well as the equality rules on inductive types and constructors.

The module subtyping rules:
  • MSUB-SIG
    E;Spec1;...;Specn[] |- Speci <: Spec's(i) for i=1..n
    s : {1... n} ® {1... m} injective
    E[] |- Sig Spec1;...;Specn  End <: Sig Spec'1;...;Spec'm  End
  • MSUB-FUN
    E[] |- T1' <: T1          E; ModS(X:T1')[] |- T2 <: T2'
    E[] |- Funsig(X:T1) T2 <: Funsig(X:T1') T2'
  • MSUB-EQ
    E[] |- T1 <: T2          E[] |- T1 = T1'          E[] |- T2 = T2'
    E[] |- T1' <: T2'
  • MSUB-REFL
    E[] |- WF(T)
    E[] |- T <: T
Specification subtyping rules:
  • ASSUM-ASSUM
    E[] |- U1 £bdiz U2
    E[] |- Assum()(c:U1) <: Assum()(c:U2)
  • DEF-ASSUM
    E[] |- U1 £bdiz U2
    E[] |- Def()(c:=U1:t) <: Assum()(c:U2)
  • ASSUM-DEF
    E[] |- U1 £bdiz U2        E[] |- c =bdiz t2
    E[] |- Assum()(c:U1) <: Def()(c:=U2:t2)
  • DEF-DEF
    E[] |- U1 £bdiz U2        E[] |- t1 =bdiz t2
    E[] |- Def()(c:=U1:t1) <: Def()(c:=U2:t2)
  • MODS-MODS
    E[] |- T1 <: T2
    E[] |- ModS(m:T1) <: ModS(m:T2)
  • MODEQ-MODS
    E[] |- T1 <: T2
    E[] |- ModSEq(m:T1==p) <: ModS(m:T2)
  • MODS-MODEQ
    E[] |- T1 <: T2        E[] |- m = p2
    E[] |- ModS(m:T1) <: ModSEq(m:T2==p2)
  • MODEQ-MODEQ
    E[] |- T1 <: T2        E[] |- p1 = p2
    E[] |- ModSEq(m:T1==p1) <: ModSEq(m:T2==p2)
  • MODTYPE-MODTYPE
    E[] |- T1 <: T2        E[] |- T2 <: T1
    E[] |- ModType(S:=T1) <: ModType(S:=T2)
Verification of the specification
  • IMPL-SPEC
    WF(E;Spec)[]
    Spec is one of Def, Assum, Ind, ModType
    E[] |- Spec : Spec
  • MOD-MODS
    WF(E; ModS(m:T))[]        E[] |- M : T
    E[] |- Mod(m:T:=M) : ModS(m:T)
  • MOD-MODEQ
    WF(E; ModSEq(m:T==p))[]           E[] |- p = p'
    E[] |- Mod(m:T:=p') : ModSEq(m:T==p')
New environment formation rules
  • WF-MODS
    WF(E)[]        E[] |- WF(T)
    WF(E; ModS(m:T))[]
  • WF-MODEQ
    WF(E)[]           E[] |- p : T
    WF(E, ModSEq(m:T==p))[]
  • WF-MODTYPE
    WF(E)[]           E[] |- WF(T)
    WF(E, ModType(S:=T))[]
  • WF-IND
    WF(E;Ind()[GP](GC:=GI ))[]
    E[] |- p: Sig Spec1;...;Specn;Ind()[GP'](GC':=GI' );...  End :
    E[] |- Ind()[GP'](GC':=GI' ){p.l/l}l Î labels(Spec1;...;Specn) <: Ind()[GP](GC:=GI )
    WF(E; Indp()[GP](
    GC:=GI  )
    		)[]
Component access rules
  • ACC-TYPE
    E[G] |- p : Sig Spec1;...;Speci;Assum()(c:U);...  End
    E[G] |- p.c : U{p.l/l}l Î labels(Spec1;...;Speci)
  • E[G] |- p : Sig Spec1;...;Speci;Def()(c:=U:t);...  End
    E[G] |- p.c : U{p.l/l}l Î labels(Spec1;...;Speci)
  • Notice that the following rule extends the delta rule defined in section 4.3
  • ACC-DELTA
    E[G] |- p : Sig Spec1;...;Speci;Def()(c:=U:t);...  End
    E[G] |- p.c |>d t{p.l/l}l Î labels(Spec1;...;Speci)
  • in the rules below we assume GP is [p1:P1;...;pr:Pr], GI is [I1:A1;...;Ik:Ak], and GC is [c1:C1;...;cn:Cn]
  • ACC-IND
    E[G] |- p : Sig Spec1;...;Speci;Ind()[GP](GC:=GI );...  End
    E[G] |- p.Ij : (p1:P1)...(pr:Pr)Aj{p.l/l}l Î labels(Spec1;...;Speci)
    E[G] |- p : Sig Spec1;...;Speci;Ind()[GP](GC:=GI );...  End
    E[G] |- p.cm : (p1:P1)...(pr:Pr)Cm{Ij/(Ij p1... pr)}j=1... k{p.l/l}l Î labels(Spec1;...;Speci)
  • ACC-INDP
    E[] |- p: Sig Spec1;...;Specn; Indp'()[GP](
    GC:=GI  )
    		;...  End :
    E[] |- p.Ii |>d p'.Ii
    E[] |- p: Sig Spec1;...;Specn; Indp'()[GP](
    GC:=GI  )
    		;...  End :
    E[] |- p.ci |>d p'.ci
  • ACC-MOD
    E[G] |- p : Sig Spec1;...;Speci; ModS(m:T);...  End
    E[G] |- p.m : T{p.l/l}l Î labels(Spec1;...;Speci)
  • E[G] |- p : Sig Spec1;...;Speci; ModSEq(m:T==p');...  End
    E[G] |- p.m : T{p.l/l}l Î labels(Spec1;...;Speci)
  • ACC-MODEQ
    E[G] |- p : Sig Spec1;...;Speci; ModSEq(m:T==p');...  End
    E[G] |- p.m = p'{p.l/l}l Î labels(Spec1;...;Speci)
  • ACC-MODTYPE
    E[G] |- p : Sig Spec1;...;Speci; ModType(S:=T);...  End
    E[G] |- p.S = T{p.l/l}l Î labels(Spec1;...;Speci)
The function labels() is used to calculate the set of label of the set of specifications. It is defined by labels(Spec1;...;Specn)=labels(Spec1)È...;Èlabels(Specn) where labels(Spec) is defined as follows:
  • labels(Assum(G)(c:U))={c},
  • labels(Def(G)(c:=U:t))={c},
  • labels(Ind(G)[GP](GC:=GI ))=dom(GC)Èdom(GI),
  • labels( ModS(m:T))={m},
  • labels( ModSEq(m:T==M))={m},
  • labels( ModType(S:=T))={S}

    WF(E; ModS(m:T);E')[G]

Module path equality is a transitive and reflexive closure of the relation generated by ACC-MODEQ and ENV-MODEQ.
  • MP-EQ-REFL
    E[G] |- p : T
    E[G] |- p : p
  • MP-EQ-TRANS
    E[G] |- p = p'      E[G] |- p' = p''
    E[G] |- p' = p''
