type 'a with_vars = Names.Id.Set.t * (Names.Name.t * Names.Id.t) list * 'a

When term matching a rule is found, with_vars informs about the set of actual binder names of this term and the pairs (x,y) of (notation-unbound) binder name x of the pattern and corresponding binder name y in the term; e.g. when matching the term "fun '((y,z) as c) b => t" against the pattern "fun x a => u" (when x is not bound in the notation) the actual binder names include c,y,z,b and the matching pairs are (x,c);(b,a)

Instances of notation variables, with their type as interpreted in a pattern

In a result subst,(b,n,more_args) of match_notation_constr_cases_pattern or match_notation_constr_ind_pattern, b tells when the notation is a notation for a pattern of the form @f in which case implicit arguments are deactivated by convention. Otherwise, n tells how many arguments are involved in the notation and more_args are the extra arguments in case the pattern is a partially apply constructor. For instance, if the pattern is C ?x ?y with notation, say, "x,y" and the term is C t1 t2 t3 t4, then n is 2 and more_args is t3;t4 (the information is needed so that, later on, if e.g. C has its 3rd argument implicit, the term should be written "x,y t4"
